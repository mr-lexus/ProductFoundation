# Структура монорепозитория

[English version](./monorepo-layout.md)

```text
apps/
  api/                    сборка NestJS-приложения, серверные модули продукта, фоновый процесс
  web/                    запуск в браузере
  mobile/                 запуск Capacitor и нативные адаптеры
  desktop/                запуск Tauri и адаптеры для настольной платформы

packages/
  contracts/              RPC-схемы и DTO продукта
  frontend-app/           общее React-приложение продукта
  rpc/                    протокол, независимый от фреймворка
  rpc-client/             клиент, независимый от фреймворка
  rpc-server/             исполнитель процедур, независимый от фреймворка
  backend-core/           серверные интерфейсы и координация надёжного выполнения
  backend-postgres/       адаптеры PostgreSQL и миграции основы
  config/                 общие настройки инструментов

docs/
  adr/                    долгосрочные решения и их компромиссы
  architecture/           текущая архитектура и эксплуатация
```

## Ответственность

`apps/*` задают границы запуска и развёртывания. Приложения могут импортировать
пакеты, но пакеты не должны импортировать конкретные оболочки.

`@product-foundation/*` — техническая основа без привязки к предметной области.
`@app/*` — слой продукта, который команда развивает после копирования шаблона.

`packages/contracts` содержит только схемы и типы внешних границ.
`packages/frontend-app` отвечает за общий интерфейс продукта на всех платформах.
`apps/api/src/modules` — за серверные функциональные модули.

## Тонкие оболочки

Не реализуйте одну функцию отдельно для Web, Mobile и Desktop. Помещайте её
в `frontend-app`, а различия платформ передавайте через явные адаптеры.

В оболочках уместны уведомления, работа с файловой системой, системная отправка
контента, жизненный цикл окон и запуск платформы.

Каждая оболочка владеет `index.html`, `src/main.tsx`, `src/runtime.ts`
и `vite.config.ts`. Результаты сборки находятся в `apps/web/dist`,
`apps/mobile/dist` и `apps/desktop/dist`. Нативная упаковка никогда не читает
результат Web. Каталоги ресурсов оболочек не должны быть общими.

Вспомогательный `native-runtime-config.mts` находится в `scripts`, поскольку
нужен и Node-скриптам запуска, и конфигурации оболочек. Функции фронтенда его
не импортируют.

## Публичные интерфейсы

Импорты между пакетами используют экспорты пакета. Импорты между слайсами
фронтенда используют `index.ts` слайса. Нельзя обращаться к внутренним путям
`src` другого пакета или слайса.
