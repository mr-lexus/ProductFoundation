# Готовность основы

[English version](./foundation-readiness.md)

## Статус

Основа находится в публичной бета-версии и готова к копированию после успешных
приёмочных проверок ниже. Заявление о готовности базовой инфраструктуры
к рабочей эксплуатации требует опубликованного примера надёжной мутации
и успешного полного CI. Предметной области продукта, провайдера идентификации
и дизайн-системы здесь нет.

## Что обеспечивает основа

- Разделение ответственности пакетов без привязки к продукту и автоматические
  проверки архитектурных границ.
- Воспроизводимое рабочее пространство Node.js 24, однозначное форматирование и линтинг.
- NestJS 11 + Fastify 5, нативный ESM и версионированный RPC на основе контрактов.
- Атомарную идемпотентность PostgreSQL: состояние, outbox и проверенный результат
  фиксируются одной транзакцией мутации.
- Транзакции PostgreSQL 17, пространства имён миграций и готовый каталог миграций продукта.
- Общую область данных либо контекст арендатора с обязательным принудительным RLS.
- Транзакционный outbox с ограниченным временем владения, отдельными токенами
  захвата, повторами, сохранением необработанных сообщений и сроками хранения.
- Проверки состояния API и фонового процесса, метрики Prometheus и безопасную
  структурированную диагностику.
- Реальные сборки Web, Mobile и Desktop, а также CSP Tauri.
- Образ Docker, полный smoke-тест Compose и проверку оболочек в CI.

## Приёмочные проверки

```bash
pnpm install --frozen-lockfile
pnpm check
TEST_DATABASE_URL=postgresql://... pnpm check:ci
pnpm build
pnpm smoke:api
pnpm smoke:compose
pnpm check:native
```

`check:ci` требует PostgreSQL и не допускает молчаливого пропуска интеграционных
тестов. Для `check:native` нужны локальные инструменты Rust/Tauri. CI
устанавливает системные зависимости Linux и дополнительно собирает Tauri
без формирования установочного пакета.

## Проверки фронтенда и платформ

Три независимые сборки используют одно React-приложение.
`pnpm test:frontend-artifacts`, затем `pnpm check:frontend-artifacts`
проверяют параллельные сборки, точки входа, пути упаковки, манифест, иконки
и отсутствие PWA в нативных результатах. `pnpm --filter @app/web test:pwa`
проверяет регистрацию рабочего service worker, переходы по оболочке SPA
без сети и отсутствие кеширования API. Обязательного теста обновления
между двумя сборками намеренно нет.

Для каждого PR CI собирает Android assembleDebug и Tauri под Linux.
Tauri для Windows и macOS, а также неподписанная сборка для симулятора iOS
выполняются для затрагивающих их PR, еженедельно и вручную. Статус
`native-coverage` требует успеха всех применимых заданий и явно сообщает
о пропуске для остальных PR. При push в основную ветку остаются базовые
задания; расширенные выбираются событиями PR, расписания и ручного запуска.

Проверка конфигурации Capacitor, генерация и синхронизация проектов, нативная
компиляция и запуск на устройстве — разные уровни проверки. Для компиляции iOS
нужны macOS и Xcode; синхронизация под Linux сборкой iOS не является.
Таблица origin сверена с конфигурацией и исходниками фреймворков и проверена
точными CORS preflight-тестами, но не сквозными тестами на устройствах.
Упаковка для магазинов, подпись, нотариализация и проверка интерфейса
на устройствах остаются задачами продукта.

## Что выбирает продукт

- Провайдера идентификации и сессий, систему прав.
- Область данных `global` или `tenant`.
- Схему данных и бизнес-модули.
- Дизайн-систему и интерфейс.
- Объектное хранилище, поиск, обмен в реальном времени и внешние интеграции.
- Платформу развёртывания, секреты и экспорт телеметрии.
