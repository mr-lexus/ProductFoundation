# Переменные окружения

[English version](./environment-contract.md)

Конфигурация разбирается один раз при запуске процесса. Неверные значения
останавливают запуск; код функций не должен читать `process.env` напрямую.

| Переменная | Кто использует | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `NODE_ENV` | API/фоновый процесс | `development` | `development`, `test`, `production` |
| `DATABASE_URL` | API/фоновый процесс | нет | Подключение с минимальными правами; обязательно для фонового процесса и рабочего API |
| `MIGRATION_DATABASE_URL` | миграции | `DATABASE_URL` | Привилегированное подключение только для миграций; не передавать API и фоновому процессу |
| `DATABASE_POOL_MAX` | API/фоновый процесс | `10` | Число соединений на процесс |
| `DATABASE_CONNECTION_TIMEOUT_MS` | API/фоновый процесс | `5000` | Положительное целое число |
| `DATA_SCOPE_MODE` | API | `global` | Доступные через DI интерфейсы режима `global` или `tenant` |
| `PRODUCT_MIGRATION_NAMESPACE` | миграции | `app` | Постоянное пространство имён миграций продукта |
| `PORT` | API | `3001` | Порт процесса или контейнера API |
| `CORS_ORIGINS` | API | локальные источники | Обязательно в рабочем окружении |
| `MAX_RPC_BODY_BYTES` | API | `1048576` | Ограничение тела запроса Fastify |
| `RATE_LIMIT_MAX` | API | `300` | Базовый лимит на процесс/IP |
| `RATE_LIMIT_WINDOW_MS` | API | `60000` | Окно ограничения частоты запросов |
| `TRUST_PROXY` | API | `false` | Включать только за доверенным прокси |
| `LOG_LEVEL` | API | `info` | Уровень логов, совместимый с Pino |
| `WORKER_BATCH_SIZE` | фоновый процесс | `10` | Максимум одновременно захваченных и обрабатываемых сообщений: 1–50 |
| `WORKER_LEASE_MS` | фоновый процесс | `30000` | Время владения сообщением |
| `WORKER_MAX_ATTEMPTS` | фоновый процесс | `10` | Число попыток до перевода в необработанные |
| `WORKER_POLL_INTERVAL_MS` | фоновый процесс | `1000` | Пауза при отсутствии работы или ошибке |
| `WORKER_METRICS_PORT` | фоновый процесс | `9464` | Порт проверок состояния и Prometheus |
| `WORKER_MAINTENANCE_INTERVAL_MS` | фоновый процесс | `30000` | Интервал обновления статистики и очистки |
| `WORKER_CLEANUP_BATCH_SIZE` | фоновый процесс | `500` | Размер порции удаления по сроку хранения |
| `WORKER_PROCESSED_RETENTION_MS` | фоновый процесс | `604800000` | Срок хранения обработанных строк |
| `WORKER_DEAD_LETTER_RETENTION_MS` | фоновый процесс | `2592000000` | Срок хранения сообщений с исчерпанными попытками |

Переменные только для Compose:

- `API_PORT` публикует порт API `3001` на выбранном порту хоста.
- `DATABASE_PORT` публикует порт PostgreSQL `5432` на выбранном порту хоста.
- `COMPOSE_PROJECT_NAME` разделяет контейнеры и тома скопированных проектов.
- `COMPOSE_DOCKER_VIA_WSL=true` заставляет Windows-скрипт smoke-проверки
  вызывать Docker через `wsl.exe`. Это настройка локальных инструментов,
  а не конфигурация приложения.

Переменные сборки фронтенда:

- Web использует `VITE_API_URL`, если она задана; иначе при разработке —
  localhost:3001, в рабочей сборке — тот же origin, что у страницы. Обычная
  загрузка файлов окружения Vite сохраняется.
- Mobile и Desktop требуют точный `VITE_API_URL` из окружения оболочки или CI.
  Конфигурация Vite проверяет и встраивает именно его; нативные .env-файлы
  не могут подменить значение. Рабочая сборка и CI требуют HTTPS без обходных настроек.
- Локальная разработка Desktop допускает HTTP. Для Mobile нужны
  `NATIVE_ALLOW_INSECURE_API=true` и `build:mobile:dev` либо `cap:sync:dev`.
  В рабочей сборке и CI флаг отклоняется. Синхронизация Capacitor для разработки
  передаёт разрешение HTTP в настройки Android cleartext/mixed-content;
  рабочая синхронизация его удаляет. Поведение iOS ATS всё ещё нужно проверять
  на Mac и устройстве; HTTPS — переносимый вариант для разработки.
- Для live reload одновременно нужны `cap:sync:dev`, `CAP_LIVE_RELOAD=true`
  и `CAP_SERVER_URL`. Рабочая синхронизация и CI это запрещают.
  `CAP_SERVER_URL` — точный HTTP(S) origin.
- Платформа задаётся литералом в оболочке. `VITE_APP_PLATFORM`
  и `VITE_APP_TITLE` удалены.

## Фактические источники запросов фронтенда

Origin — сочетание схемы, хоста и порта, от которого браузер или WebView
отправляет запрос. В проверенной конфигурации:

| Среда | Origin |
| --- | --- |
| Разработка Web | http://127.0.0.1:1420; локальный API также принимает localhost |
| Capacitor с live reload | Точный CAP_SERVER_URL, обычно адрес локальной сети на порту 1421 |
| Разработка Tauri на всех настольных ОС | http://127.0.0.1:1422 |
| Упакованный Capacitor для iOS | capacitor://localhost |
| Упакованный Capacitor для Android | https://localhost |
| Упакованный Tauri для Windows | http://tauri.localhost |
| Упакованный Tauri для macOS/Linux | tauri://localhost |
| Развёрнутый Web/PWA | HTTP(S) origin сайта; для рабочего PWA нужен HTTPS |

Хост и схемы Capacitor, а также `useHttpsScheme=false` в Tauri заданы явно
и проверяются. Соответствия сверены с установленной конфигурацией Capacitor 8.4.1
и обработкой протокола Tauri 2.11.5: см.
[конфигурацию Capacitor](https://capacitorjs.com/docs/config)
и [исходный код закреплённой версии Tauri](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/manager/mod.rs).
Тесты конфигурации проверяют каждое соответствие, включая Windows, а тесты
preflight API — точное разрешение и запрет источников. Это не сквозные тесты
на устройствах и WebView.

В `CORS_ORIGINS` необходимо явно перечислить источники, которые действительно
использует продукт. Источники упакованных нативных приложений не добавляются
в список API по умолчанию. Помимо HTTP(S), принимаются только точные строки
`capacitor://localhost` и `tauri://localhost`. Произвольные схемы, подстановки
и непрозрачный origin `null` запрещены. Изменение нативной схемы или хоста
требует согласованного обновления конфигурации, списка разрешений и тестов.
На физическом устройстве localhost означает само устройство; API должен
иметь доступный ему адрес. CORS не заменяет аутентификацию.

Рабочие секреты поступают из хранилища секретов платформы.
`.env.example` — только локальный образец. Не записывайте в логи URL базы,
заголовки авторизации, cookies, тела запросов, содержимое документов или токены.
