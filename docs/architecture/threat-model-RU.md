# Модель угроз основы

[English version](./threat-model.md)

## Защищаемые данные

- Строки PostgreSQL, принадлежащие продукту и арендаторам.
- Данные аутентификации и сессий, добавленные продуктом.
- Сохранённые ответы идемпотентности и содержимое сообщений outbox.
- Учётные данные владельца миграций и рабочей роли базы.
- Эксплуатационные логи, метрики и сведения о сообщениях с исчерпанными попытками.

## Границы доверия

Браузерные и нативные клиенты не считаются доверенными. Вход RPC, заголовки
и выход проверяются на границе протокола. Рабочей роли API разрешён доступ
к таблицам основы, но в режиме tenant ей нельзя обходить RLS таблиц продукта.
Учётные данные миграций имеют больше прав и не должны попадать в процессы API
или фонового обработчика. Обработчики outbox обладают привилегиями для чтения
сообщений; их следует проверять как код, выполняющий внешние действия.

## Основные меры защиты

- Точный список источников CORS, ограничения размера и частоты запросов,
  строгая проверка JSON media type.
- Логи без чувствительных данных и метрики с ограниченным числом сочетаний меток.
- Интерфейсы авторизации продукта с запретом доступа по умолчанию.
- Рабочие tenant-роли без `SUPERUSER` и `BYPASSRLS`, принудительный RLS.
- Атомарные транзакции состояния, outbox и идемпотентности.
- Отдельный токен каждого захвата сообщения outbox, ограниченные повторы,
  сохранение необработанных сообщений и явный повторный запуск.
- Разные учётные данные для миграций и рабочих процессов; неизменяемые миграции
  с контрольными суммами.
- Закреплённые версии CI-действий и базовых образов контейнеров.

## Ответственность продукта

Основа не выбирает идентификацию пользователей, хранилище сессий, систему прав,
облачную изоляцию, хранилище секретов, доверенные корневые сертификаты TLS базы,
правила защиты от злоупотреблений или ответственного за инциденты. До приёма
трафика каждый продукт должен зафиксировать эти решения, проверить авторизацию
и tenant-политики, провести восстановление из резервной копии и учения
по реагированию на инциденты.

Таблицы идемпотентности и outbox — системные, они не служат репозиториями данных
арендаторов. API и фоновый процесс работают с несколькими областями через узкие
адаптеры; продуктовые модули в режиме tenant не получают прямой доступ к SQL.
Сообщения outbox должны содержать только данные, необходимые обработчику:
фоновая обработка и сроки хранения могут продлить их существование.
