# План развития технической основы

[English version](./implementation-roadmap.md)

Этот план касается только технической основы. План продукта, интерфейс
и дизайн-система создаются после копирования репозитория.

## Выполнено

### Границы и инструменты

- Модульный монолит и тонкие платформенные оболочки.
- Нейтральные пакеты `@product-foundation/*` и заменяемый слой `@app/*`.
- NestJS/Fastify только в сборке приложения и транспортном слое.
- Направление зависимостей фронтенда по FSD.
- Архитектурная проверка импортов, манифестов пакетов и циклов зависимостей.
- Node.js 24, lockfile pnpm, форматирование и линтинг Biome.

### Контракты и платформы

- Версионированный RPC на основе контрактов и проверка Zod во время выполнения.
- Общий идентификатор запроса, типизированные ошибки и отмена.
- Обязательный исполнитель надёжной идемпотентной операции для каждой
  RPC-мутации с проверкой выхода до фиксации транзакции.
- Независимые точки входа Web, Mobile и Desktop со своими каталогами dist.
- PWA только для Web: generateSW, предложение обновления и отсутствие кеша API.
- Web API на том же origin, обязательный URL API для нативных сборок и CSP Tauri.

### Данные и надёжность

- Пул PostgreSQL, транзакции и проверка готовности.
- Миграции основы и готовые пространство имён и каталог миграций продукта.
- Область операции `global | tenant` без фиктивных арендаторов.
- Атомарная транзакция идемпотентности для состояния, outbox и проверенного ответа.
- Транзакционный outbox, параллельная обработка захваченных сообщений,
  отдельные токены захвата, повторы, необработанные сообщения и сроки хранения.
- Состояние фонового процесса, метрики Prometheus и корректное завершение.

### Доставка

- Структурированная диагностика без чувствительных данных, Helmet, CORS,
  ограничения размера и частоты запросов.
- Тесты пакетов, API и интеграции с PostgreSQL.
- Рабочие сборки Web/API и smoke-тест скомпилированного приложения.
- Современный pnpm deploy, полный smoke-тест Docker Compose и GitHub Actions.
- Отдельная CI-проверка оболочек Capacitor/Tauri.

## Следующий этап — конкретный продукт

1. Выполните и проверьте `pnpm product:rename -- ... --write`.
2. Выберите `DATA_SCOPE_MODE`, модель идентификации, сессий и прав.
3. Создайте первый контракт и серверный функциональный модуль продукта.
4. Добавьте первую миграцию в `apps/api/migrations`.
5. Создайте дизайн-систему и первый сквозной сценарий фронтенда.
6. Добавьте проверки авторизации и изоляции, соответствующие продукту.
7. Настройте секреты, входящий трафик, резервные копии и экспорт телеметрии.

## Не добавлять заранее

Микросервисы, Redis, внешние очереди и поиск, CRDT и хранилище распределённых
трассировок требуют подтверждённой необходимости и отдельного ADR.
