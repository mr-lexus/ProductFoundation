# Жизненный цикл шаблона и обновления

[English version](./template-lifecycle.md)

Product Foundation выпускается как версионированный снимок шаблона. Его копия
становится самостоятельным репозиторием продукта, без канала автоматического
обновления пакетов.

## Начало продукта

1. Скопируйте выпуск с тегом, а не произвольный коммит ветки.
2. Сохраните файл `FOUNDATION_VERSION`.
3. Выполните описанное в документации переименование и полный набор приёмочных проверок.
4. Зафиксируйте в ADR продукта решения об идентификации пользователей, области данных
   и развёртывании.

## Перенос изменений из основы

1. Прочитайте историю всех выпусков после записанной версии.
2. В первую очередь оцените исправления безопасности, целостности данных и миграций.
3. Сравните теги выпусков и перенесите нужные изменения через обычный PR с ревью.
4. Повторно проверьте авторизацию продукта, изоляцию арендаторов, миграции и восстановление.
5. Обновите `FOUNDATION_VERSION` только после завершения переноса и проверки.

Команды автоматического слияния намеренно нет. Миграции, контракты и конфигурация
развёртывания продукта делают обновление шаблона без участия команды небезопасным.
Переход к публикации пакетов в реестре потребует отдельного ADR и правил совместимости.

Возможная будущая команда `foundation doctor` могла бы сравнивать
`FOUNDATION_VERSION` с данными опубликованных выпусков и показывать важные
исправления безопасности, целостности данных и надёжности. Она не должна
автоматически сливать код или обновлять миграции. Это отдельная задача,
для которой сначала нужен стабильный источник сведений о выпусках.
