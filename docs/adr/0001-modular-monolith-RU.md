# ADR 0001: Сначала модульный монолит

[English version](./0001-modular-monolith.md)

- Статус: принято
- Дата: 2026-07-11

## Контекст

Шаблон должен подходить для разных продуктов и большого числа пользователей.
В команду могут входить ИИ-агенты. Раннее внедрение микросервисов увеличивает
число единиц развёртывания, распределённых транзакций и контрактов, усложняет
наблюдаемость — ещё до того, как измерены границы нагрузки.

## Решение

Бэкенд разворачивается как модульный монолит. Бизнес-код организован
по функциональным областям. Модули общаются через явные прикладные API,
а не через таблицы друг друга. Отдельная точка входа фонового процесса
может использовать те же модули и контракты.

После решения о хранении данных источником истины становится PostgreSQL.
Асинхронные действия публикуются через транзакционный outbox. Поиск,
уведомления и обмен в реальном времени — проекции или потребители данных,
а не владельцы первичных записей.

## Последствия

Преимущества:

- атомарные транзакции для сценариев продукта;
- простой локальный запуск и развёртывание;
- видимые и проверяемые границы;
- возможность позже выделить модуль по измеренной причине.

Издержки:

- нужна дисциплина импортов и ответственности;
- тяжёлым задачам нужны отдельные очереди или модели чтения;
- одна база требует индексов с учётом арендаторов и дисциплины миграций.

Для выделения сервиса нужны владелец, независимое масштабирование или граница
безопасности, измеренная проблема и план распределения ответственности за данные.
