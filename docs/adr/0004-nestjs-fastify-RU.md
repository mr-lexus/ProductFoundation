# ADR 0004: NestJS с HTTP-адаптером Fastify

[English version](./0004-nestjs-fastify.md)

- Статус: принято
- Дата: 2026-07-11

## Контекст

Бэкенд должен оставаться удобным для долгосрочной работы людей и ИИ-агентов.
Ему нужны явные бизнес-модули, внедрение зависимостей, управление жизненным
циклом, guards, фильтры, наблюдаемость и несколько точек входа. Ручная сборка
приложения на Hono была компактной, но не давала единой модели для этих задач.

Общие контракты, прикладные сценарии и правила предметной области при этом
не должны зависеть от выбранного фреймворка.

## Решение

Использовать NestJS как фреймворк серверного приложения, а официальный адаптер
Fastify — для обработки HTTP.

NestJS отвечает за:

- корневой модуль и функциональные модули;
- внедрение зависимостей и жизненный цикл провайдеров;
- контроллеры;
- глобальные фильтры исключений, guards и перехватчики;
- запуск приложения и корректное завершение работы.

Каждая функциональная область экспортирует тонкий Nest-модуль из слоя
`transport`. Чистые обработчики и сценарии подключаются явными токенами
провайдеров и фабриками. Код domain и application не получает декораторы Nest.

Fastify отвечает за разбор HTTP и ограничение размера тела. Глобальный фильтр
исключений приводит ошибки фреймворка и парсера к общему формату ошибок RPC.

`RpcException` из Nest microservices не используется. Текущий протокол —
HTTP JSON: его граница находится в `@product-foundation/rpc`, а процедуры
продукта — в `packages/contracts`, без опоры на транспортные типы Nest.

## Последствия

Преимущества:

- единая модель модулей бэкенда;
- стандартные средства DI, жизненного цикла и тестирования;
- явные места для guards авторизации, наблюдаемости и конфигурации;
- ограничение Fastify срабатывает до полной загрузки слишком большого тела;
- ядро тестируется без тестового контейнера Nest.

Издержки:

- декораторы и DI требуют настройки компилятора;
- запуск сложнее, чем у минимального приложения Hono;
- есть риск создавать лишние `@Injectable()`-обёртки для каждого сценария;
- плагины Fastify нужно проверять на совместимость с адаптером Nest.

Архитектурная проверка запрещает импорты NestJS/Fastify вне `src/app`
и `src/modules/*/transport`, а импорты Hono — полностью.
