# ADR 0008: Атомарная идемпотентность с блокировкой на время транзакции

[English version](./0008-atomic-idempotency-advisory-lock.md)

- Статус: принято
- Дата: 2026-07-16

## Контекст

Изначально журнал записывал строку `processing` и выполнял работу продукта
в одной транзакции PostgreSQL. Конкурирующий `INSERT ... ON CONFLICT` ждёт
незафиксированную строку, поэтому заявленные перехват после истечения срока
и быстрый ответ `in_progress` при обычном выполнении были недостижимы.
Разделение захвата и работы на разные транзакции сделало бы журнал видимым,
но нарушило бы более сильную гарантию: состояние продукта, outbox и проверенный
ответ фиксируются атомарно.

## Решение

- Вся мутация остаётся одной транзакцией PostgreSQL.
- `pg_try_advisory_xact_lock(hashtextextended(identity, 0))` обеспечивает
  выполнение только одной операции для сочетания
  `(scope, procedure, idempotency key)`, без ожидания блокировки.
- Если блокировка не получена, немедленно возвращается `in_progress`.
- Хранятся только завершённые ответы; состояния `processing`, `failed`,
  срок владения и столбцы владельца удаляются.
- Завершённый ключ возвращает сохранённый ответ; другой хеш запроса вызывает
  конфликт; просроченные результаты удаляются внутри последующих транзакций мутаций.

Редкая коллизия хеша блокировки может лишь временно вернуть ложный
`in_progress`. Она не позволяет выполнить или раскрыть другую операцию,
поэтому отказ остаётся безопасным.

## Последствия

Поведение при конкуренции теперь соответствует реализации, а в журнале нет
недостижимых состояний. Мутации по-прежнему должны быть короткими транзакциями;
медленная внешняя работа принадлежит outbox. Будущая реализация на другой базе
обязана сохранить атомарность завершения.

Миграция `0003_atomic_idempotency.sql` удаляет недостижимые состояния и столбцы
бета-версии. При обновлении с ранней беты нужно остановить старые процессы,
выполняющие мутации, применить миграции и затем развернуть новую версию.
Это миграция обслуживания до стабильного выпуска, а не миграция для постепенного
обновления работающего продукта.
