# ADR 0006: Область операции и механизмы надёжного выполнения

[English version](./0006-tenant-and-durable-execution-primitives.md)

## Статус

Принято. Конкурентное выполнение идемпотентных операций уточнено в ADR 0008.

## Контекст

Шаблон должен поддерживать продукты с общей областью данных и продукты
с несколькими арендаторами. Нужны безопасные повторы и асинхронные внешние
действия без обязательных Redis или внешнего брокера с первого дня.

## Решение

- Надёжные операции используют `OperationScope`: `{ kind: "global" }`
  либо явный `TenantScope`.
- `DATA_SCOPE_MODE=global` предоставляет обычные интерфейсы SQL и транзакций.
- `DATA_SCOPE_MODE=tenant` предоставляет продуктовым модулям только
  `TenantTransactionRunner`. Адаптер PostgreSQL устанавливает
  `app.tenant_id` на время транзакции.
- Таблицы арендаторов обязаны включать и принудительно применять RLS,
  иметь явную политику, использовать роль без прав суперпользователя
  и проходить проверки метаданных и запрета доступа между арендаторами.
- Авторизация запрещает доступ по умолчанию и всегда получает область операции.
- Каждая RPC-мутация требует `X-Idempotency-Key` и надёжный исполнитель обработчика.
- Состояние продукта, сообщения outbox, проверенный выход и завершение записи
  идемпотентности используют одну транзакцию PostgreSQL, явно переданную обработчику.
- Записи идемпотентности содержат хеш запроса, TTL и завершённые ответы.
  Неблокирующая рекомендательная блокировка на время транзакции возвращает
  `in_progress` для конкурирующего дубликата; см. ADR 0008.
- Изменения состояния и сообщения outbox записываются в одной транзакции.
- Доставка outbox использует `FOR UPDATE SKIP LOCKED`, ограниченное время
  владения с отдельным защитным токеном для каждого захвата, ограниченные
  повторы, сохранение необработанных сообщений и идемпотентные обработчики.
- Сроки хранения обработанных сообщений и сообщений с исчерпанными попытками
  настраиваются. Метрики показывают число ожидающих сообщений, возраст самого
  старого, повторы, необработанные сообщения и очистку.

## Последствия

Простым продуктам не нужны фиктивные арендаторы. В продуктах с арендаторами
изоляция видна в типах и предоставляемых через DI интерфейсах.
PostgreSQL остаётся начальным механизмом надёжной координации. Внешняя очередь
может заменить опрос только после ADR, основанного на измеренной нагрузке.
