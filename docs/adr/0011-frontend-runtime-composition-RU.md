# ADR 0011: Независимые точки входа и сборки фронтенда

[English version](./0011-frontend-runtime-composition.md)

- Статус: принято
- Дата: 2026-10-04

## Контекст

Раньше все сборки фронтенда использовали точку входа Web и перезаписывали его
dist. Нативная упаковка зависела от ресурсов Web, а параллельные сборки были
небезопасны. Общее приложение уже принимало конфигурацию, а RPC-клиент —
переданную извне реализацию fetch.

## Решение

- Каждая оболочка владеет index.html, основной точкой входа, конфигурацией
  Vite, литералом платформы и своим каталогом dist.
- Одно `@app/frontend-app` содержит весь интерфейс и сценарии продукта.
- При запуске конфигурация и fetch передаются непосредственно в конкретный
  API-клиент. API-провайдер предоставляет операции, которые уже нужны функциям.
- Общего контекста среды, реестра возможностей или локатора сервисов нет.
- Будущие нативные возможности получают отдельные явные абстракции только
  при появлении реальных потребителей.
- Общие зависимости собираются один раз до параллельных сборок фронтенда.
- Для разработки используются разные фиксированные порты, изолирующие
  service worker Web.
- Нативная конфигурация остаётся на границе сборки приложения.
  Вспомогательные файлы в scripts используются запуском и конфигурацией,
  но не импортируются функциями продукта.

## Последствия

Три небольших набора файлов запуска и конфигурации — намеренная настройка
трёх сред, а не три продуктовых приложения. Путь развёртывания Web сохраняется.
Пути нативной упаковки меняются; сгенерированные мобильные проекты после
этого нужно синхронизировать. Зависимости между оболочками и пересечение
результатов сборки считаются ошибками архитектурной проверки.

Поправки по фактическому устройству репозитория: общий вспомогательный файл
нативных инструментов имеет расширение `.mts`, поскольку проверка конфигурации
Capacitor использует разрешение NodeNext. Первая проверка Cargo под Windows
обнаружила отсутствие `icons/icon.ico`; контейнеры иконок Windows/macOS
созданы из существующего нейтрального PNG уже установленной Tauri CLI.
Новая зависимость для генерации ресурсов и новый источник идентичности
продукта не добавлялись.
