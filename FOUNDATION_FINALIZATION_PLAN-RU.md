# Product Foundation: план завершения основы

[English version](./FOUNDATION_FINALIZATION_PLAN.md)

## Цель

Это последняя итерация, посвящённая только основе, перед началом разработки
продукта. Объём фиксирован: устранить подтверждённые регрессии в текущих
незакоммиченных изменениях, один раз пройти полный набор приёмочных проверок,
зафиксировать воспроизводимый снимок и прекратить дальнейшую полировку основы.

Завершение означает, что **в рамках набора проверок ниже не осталось известных
блокирующих проблем основы**. Это не обещание, что будущие ревью не найдут
возможных улучшений. После закрытия плана новая работа требует потребности
продукта, воспроизведённого дефекта, сообщения об уязвимости или упавшей
обязательной проверки.

Критерий приёмки: статические проверки, все модульные тесты и тесты
инструментов проходят без исключений и повторных запусков.

Подтверждение от 2026-07-18: `pnpm check` завершился с кодом 0,

### F3. Один раз пройти полный набор приёмочных проверок

- [x] Закоммитить проверенные изменения завершения в ветке для ревью.
- [x] После push запустить проверки GitHub на точном кандидате выпуска.
- [x] Получить успех всех следующих проверок:
  - `verify`: `pnpm check:ci`, рабочая сборка, smoke-тест скомпилированного
    API и smoke-тест Compose;
  - `platform-shells`: сборка Mobile, отладочная сборка Android,
    Rust format/clippy и сборка Tauri без упаковки;
  - `rename-smoke` после настоящего переименования продукта;
  - `dependency-review`: проверка изменённых зависимостей GitHub, когда
    доступна; для приватных репозиториев без GitHub Code Security —
    аудит всего lockfile на уязвимости высокой серьёзности;
  - CodeQL `analyze`, когда GitHub Code Security доступен. В неподдерживаемом
    приватном репозитории задание обязано зафиксировать ограничение,
    а аудит lockfile остаётся обязательным.
- [x] Считать нестабильные и зависящие от окружения ошибки ошибками,
  пока причина не установлена. Не перезапускать до успеха без записи причины.
- [x] Вносить только исправления, необходимые для этого фиксированного набора.
  Новые возможности отправлять в план продукта, а не в этот план.

Критерий приёмки: ссылки на успешные запуски всех обязательных проверок
для одного коммита.

Локальное подтверждение от 2026-07-18: прошли `pnpm check`, `pnpm build`,
`pnpm smoke:api`, `pnpm build:mobile` и `pnpm check:native-security`.
Compose локально не запустился из-за недоступного Docker daemon.
Проверкам Rust потребовались инструменты CI; удалённо они прошли.

Первый удалённый запуск от 2026-07-18: `verify` прошёл. Причины остальных
ошибок установлены: Android использовал Java 11, хотя плагину Gradle нужна
минимум Java 17, а установленная библиотека Capacitor 8 Android компилируется
для Java 21; тест инструментов ожидал исходные значения после `rename-smoke`;
у приватного репозитория нет GitHub Code Security, поэтому встроенная
проверка зависимостей и загрузка CodeQL недоступны. Исправленный процесс
сохранил эти проверки для публичных репозиториев и использует аудит lockfile
на уязвимости высокой серьёзности для приватных.

Успешное удалённое подтверждение от 2026-07-18: кандидат `a7f90a9` прошёл

## Что не входит в план

Без воспроизведённой блокирующей проблемы F1–F3 нельзя добавлять:

- новые общие интерфейсы, репозитории, сервисы, адаптеры или архитектурные слои;
- провайдеры аутентификации, права продукта, дизайн-систему или бизнес-сущности;
- микросервисы, Redis, очереди помимо outbox, поиск, обмен в реальном времени
  или хранилище трассировок;
- предполагаемые заранее слои совместимости для копий основы;
- работу над процентом покрытия без названного риска или отсутствующей проверки поведения;
- обновления зависимостей, не связанные с упавшей проверкой или актуальной уязвимостью;
- переписывание документации, переименование или рефакторинг с единственным
  обоснованием «могло бы быть чище».

## Условие остановки

Работа над основой останавливается, когда F1–F4 отмечены и фиксированный
приёмочный коммит успешно проверен. После этого агент может начать новую
задачу основы только при наличии хотя бы одного основания:

1. воспроизводимый дефект;
2. упавшая обязательная проверка;
3. актуальная уязвимость, затрагивающая снимок;
4. конкретное требование продукта, которое текущая граница не поддерживает;
5. измеренные эксплуатационные данные о недостаточности текущего решения.

«Посмотреть репозиторий и улучшить всё, что найдётся» — недостаточное основание.
Ревью должно назвать риск, затронутое поведение, воспроизведение или подтверждение,
минимальное исправление и приёмочный тест. Иначе предложение отклоняется
или откладывается.

## Решение после завершения

После выполнения условия остановки начинается разработка продукта, даже если
небольшие улучшения всё ещё возможны. Работа над продуктом станет следующим
источником фактов: она лучше очередного отвлечённого архитектурного ревью
покажет, что действительно нужно изменить в основе.
