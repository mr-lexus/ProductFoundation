# Участие в проекте

[English version](./CONTRIBUTING.md)

Спасибо за вклад в Product Foundation.

## Перед изменением кода

1. Прочитайте корневой `AGENTS.md` и ближайший `AGENTS.md` в затронутом каталоге.
2. Сохраняйте `@product-foundation/*` независимым от продукта, а `@app/*` — заменяемым.
3. Записывайте долгосрочные архитектурные решения в `docs/adr`.
4. Добавляйте целевые тесты для изменений надёжности и безопасности.

## Локальная работа

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
```

Изменения адаптеров PostgreSQL требуют `TEST_DATABASE_URL` и настоящих
интеграционных тестов. Изменения конфигурации Capacitor или Tauri требуют
`pnpm check:native`.

## Предложение изменений (PR)

Посвящайте каждый PR одной задаче. Опишите проблему, выбранную границу
ответственности, сценарии отказа и результаты проверок. Не включайте секреты,
сгенерированные нативные проекты, результаты сборки и постороннее форматирование.

Об уязвимостях сообщайте по [политике безопасности](./SECURITY-RU.md),
а не через публичные issues.

Используйте [шаблон PR](./.github/pull_request_template-RU.md). Отмечайте проверки
честно: приводите команды и результаты, отдельно указывайте то, что не удалось
запустить. Пропущенные интеграционные тесты базы не подтверждают правильность
работы с данными.

## Документация на двух языках

У каждой Markdown-страницы есть английский файл и русская версия с суффиксом
`-RU.md`. Обновляйте их вместе. Первая ссылка после заголовка переключает
на перевод той же страницы; остальные локальные ссылки на документацию
сохраняют язык. Ссылки на исходники и внешнюю документацию не переводятся.

`pnpm check:docs` проверяет наличие обеих версий, переключатели, локальные
ссылки и язык переходов. Смысловую точность и естественность перевода
нужно проверять при ревью.
